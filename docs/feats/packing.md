# 容器排布与收纳空间选择

> Parent: [../index.md](../index.md)
> Related: [tag-grammar.md](tag-grammar.md)、[../requirements.md](../requirements.md)

玩家点击排序后，整理会压紧容器内布局；按 tag 收纳时也会尝试重排目标容器，
使散碎空位能够容纳新物品。先折叠、[统一堆叠](stacking.md)，再收纳与排布。

## 行为契约

### Debug 排序对比

Debug 构建在最终规划后，以同一批物品、网格尺寸与固定障碍测量原生列表排序和落位。
测试只使用独立占用缓冲，不移动真实物品、不提交事务、不触发合并或折叠，
不修改 UIFixes 或其他 mod 的补丁与配置。
日志分别记录本项目规划耗时、原生计算耗时、是否全部放入、占用行数与类别跨度。
比较固定在每个网格内部，不包含原生控制器校验、事务回滚及界面刷新。
测试的额外耗时单独报告，不计入正式整理耗时或求解预算。
测试无法执行时记录原因并继续应用正式排布；Release 编译时移除测试路径。

### 范围与锁

- 排布范围为当前根容器与带有效 tag 规则的子容器，Locked 子树跳过。
- 未打规则的容器内部不动；可以遍历它们以找到更深层带规则的目的地。
- Pinned 与 Locked 物品的位置、转置保持不变，作为固定障碍。
- 统一堆叠后目标容器保留的物品全部必留，
  不能为了装入面积更多的新物品而把它们移出或丢弃。
- 物品不重叠、不越界；只允许游戏支持的转置、过滤与移动。

### 等价物品与身份

等价物品的真实 ID 不参与布局优劣判断。先计算位置集合，再映射回真实物品：
优先保留在原网格、原坐标及原转置仍可占据的位置，剩余物品分配剩余位置。
互换必须保持模板、实际尺寸、SortType、类型内子链与各网格的过滤、必留约束一致。
固定物品不参与互换；身份映射不降低装入面积、压紧程度或类别聚合质量。

### 优先级与目标

规则之间沿用 tag 的全局优先级。每条规则先补充已有堆叠，再选择收纳候选。
移入物品形成新堆叠后，本规则剩余候选须先补充其容量，再进入后续规则；
没有被选入布局的候选也参与这次补充。
同一规则下只最大化放入面积，不优化占用行数或父子类别聚合。
未选中或游戏拒绝的候选继续尝试后续规则，不在不同优先级之间交换物品来提高面积。

每条规则联合考虑目标容器的全部网格，候选按各网格尺寸、过滤及固定障碍选择落位，
每件候选最多进入一个网格。原有物品在各自网格内重排，不跨网格搬迁。
原位填空已能装入全部候选或达到可收纳面积上限时，立即结束收纳规划。
只有能增加收纳面积时才重排腾位；等面积保留已有合法布局。
联合求解没有改善或预算耗尽时，采用逐网格的合法保底布局。

排布只接收现有物品时，要求全部保留；减少占用行数是优化目标。
最终排布对根仓库与全部规则容器的待整理网格联合求解，评价为各网格完整分数之和；
物品仍留在收纳确定的网格内，不为聚合跨容器搬迁。
所有网格先准备合法初始布局，再按输入顺序尝试下述压紧提示。
每次压紧最多领取当前剩余时间除以（尚待压紧网格数 + 1）的额度，且不超过 0.75 秒，
为后续联合阶段保留预算；提前结束的余量留给后续工作。
压紧后达到通用最优界限的网格直接保留结果，其余仍可改善的网格进入同一个联合模型，
共享扣除准备与压紧耗时后的剩余额度，不按容器面积分配独立排布次序，也不要求仓库最后。
只接受所有参与网格均完整且总分严格更优的联合结果，返回结果仍按原网格顺序对应。
压紧提示按空间余量筛选：全部物品必留、布局完整且满足已启用的类型顺序，
占用高度仍高于可用面积下界时即可尝试；只有一种类型或未启用排序也参与。
不要求存在类型先后关系，不扩大到可选收纳候选；沿用原有共享预算。
这里的高度只统计可移动物品；固定物品作为障碍占格，不能因其位于仓库底部，
就判定上方布局已最优。高度以内的可用空间须扣除实际覆盖的固定障碍。
每个网格内按占用高度、父类跨度之和、逐层子类跨度之和确定优先级。
各网格独立确定层级权重，形成完整分数后再相加，不跨网格按深度汇总。
启用自定义类别顺序时，在满足类别先后的布局中优化上述分数。
总分相同时，稳定性要求优先保留已有合法布局与原位身份，避免仅为常规排序换位。
当前布局总分更好时保留当前布局。
求解器只有进一步改善时才替换基线，避免等价解之间反复搬动。

### 重复排序稳定性要求

需求见 [F3 排序 / 装箱](../requirements.md#f3-排序--装箱)。目标是尽可能一次收敛，
而非让用户重复点击后才得到稳定结果；下列为验收要求，不表示当前实现已经满足。

- 无外部物品、锁、规则或配置变化时，连续整理应尽量保持逐物品的网格、坐标和朝向。
  相同高度或相同评分不代表布局稳定；等价物品仅交换身份也算移动。
- 没有实际质量收益的等价布局切换属于无谓变动；后续仍改善空间、顺序或聚合，
  属于首次收敛不足。两者分别报告，不通过冻结较差结果来满足稳定性。
- 回放按“输出落地后重新采集为输入”连续执行，记录每轮移动数、旋转数、各网格高度、
  同口径评分及稳定轮次；同时保留守恒、几何、固定障碍和类型顺序检查。
- 分别覆盖同会话缓存保留、预算变化触发重算和缓存失效后重算；报告缓存命中情况，
  不将缓存命中单独当作首次求解已收敛的证明。离线回放不替代游戏内事务与重采集验收。

### 按类别聚合

类别聚合只用于最终排布。全部现有物品必留；在每个网格内，
优先级依次为最小化占用高度、从顶层到最深层的类别跨度之和（含末端模板虚拟类别），
然后最小化占用格子的行坐标和、列坐标和。在同一网格内，后层收益不能抵消前层变差。
各网格完整分数相加后比较布局，不建立跨网格的父子层优先级。

对网格 `g` 内每个实际放入的类别 `c`，定义：

```text
span(g,c) = max(y_i + h_i - 1) - min(y_i)，i 为本网格内属于 c 的物品
H[g] = max(y_i + h_i)，只统计可移动物品，空网格取 0
S[g,d] = sum(span(g,c))，c 为本网格深度 d 的类别
U[g,d] = (网格 g 的高度 - 1) × 本网格深度 d 的类别数量
R[g] = sum(y)，(x,y) 为可移动物品实际占用的每个格子
C[g] = sum(x)，(x,y) 为可移动物品实际占用的每个格子
UR[g] = Width[g] × Height[g] × (Height[g] - 1) / 2
UC[g] = Width[g] × Height[g] × (Width[g] - 1) / 2

score[g] = H[g]
按 d 从 0 到最深层：
    score[g] = score[g] × (U[g,d] + 1) + S[g,d]
score[g] = score[g] × (UR[g] + 1) + R[g]
score[g] = score[g] × (UC[g] + 1) + C[g]
总目标 = 最小化 sum(score[g])
```

`y_i` 为起始行，`h_i` 为转置后的高度；计算覆盖行的跨度，而非起始行跨度。
该类别没有放入任何物品时贡献为零；单件物品也按其实际覆盖行计算。
多网格的坐标相互独立，类别跨度、上界及权重均在本网格内计算。
新增其他网格不改变现有网格的计分方式；仅在最后累加完整分数。
坐标和按转置后的整个矩形计算，不只是物品左上角：面积为 A、宽高为 w/h 的物品，
行贡献为 `A × y + A × (h - 1) / 2`，列贡献为 `A × x + A × (w - 1) / 2`。
未选候选贡献为零；固定障碍贡献恒定，不参与坐标评分。模型使用矩形坐标与转置变量，
不为每个格子增加变量。高度和类别都到下界时，只有坐标目标也到安全下界才跳过整个搜索。
这两个目标是偏好，不是每件物品只能向上或向左移动的硬约束；允许腾位时向下或向右。
优先保证高度与聚合，故不承诺消除所有上方空洞；同分仍保留原布局与原位身份。
物品归入统一树上的叶节点及全部祖先节点；父节点范围包含其所有后代物品。
深度按裁剪、压缩后的树计算；较浅分支在更深层不贡献分数，不虚构或重复填充叶节点。

- `SortType` 是排序与聚合的唯一顶层。适配层从包含 mod 注册结果的运行时手册读取完整链，
  按该类型对应的原生类别边界截断，只把边界之后的 ID 链作为 `SubcategoryPath` 交给 Core。
  边界映射集中在 `ItemCategoryHierarchy`，不按当前快照中的多数成员或本地化名称猜测。
  找不到对应边界的跨类物品直接归类型根，不能把其旧祖先移植进来；这不是删除原生第一层。
  例如 GP 币的“交换用物品 / 贵重物品”不在 Money 边界内，和三种法币一样不保留该旧子链。
  饮料的“饮食 / 饮品”截断后为空；mod 若在“饮品”下新增真正子类，该内部子链仍保留。
  HeadgearArmor、BallisticPlates、Armband、RepairKits 没有对应的原生内部树，直接归类型根，
  不借用更宽泛的“装备组件”或“特殊装备”。类型内子链再按本网格成员裁剪、压缩。
- Core 在每件物品的类型内部子链末端追加 `TemplateId` 虚拟类别，随后统一裁剪、压缩。
  没有内部子链时模板直接接在 SortType 下；模板节点与原生类别节点使用不同键空间。
  模板叶节点沿用既有深度和权重公式，不另设跨分支的模板优先级，单模板同成员节点照常压缩。
  模板聚合仍统计覆盖行跨度，不保证横向相邻；真实物品 ID 不进入类别树。
- 与父节点成员集合完全相同的子节点被压缩；存在直属成员、子节点为严格子集时仍保留。
  子节点按完整父路径区分，不因局部名称或 ID 相同而跨分支合并。
  空子链仍进入其 SortType 根；空 SortType 统一进入未识别根，不回退到原生分支。
- 数量模型、几何模型与实际评分共用此树。每个节点只建一次覆盖范围，父范围复用子范围；
  顶层跨度与类型中线顺序引用同一范围。缺席子节点不扩大父范围，全缺席节点跨度为零。
  树按请求复用；结果缓存比较 TemplateId、SortType、SubcategoryPath 和顺序配置，覆盖全部构树输入。
- 不为类别预留矩形分区，允许横向并排或穿插；不优化类别横向跨度，整体靠左由最低优先级列坐标和表达。
- Pinned 与 Locked 只作为固定障碍，不计入可移动物品的类别跨度。
- 单格与大件共同参与位置优化，不能在优化后任意填充单格导致聚合指标失真。
- 本网格内所有可移动物品共同参与几何建模，不以固定布局上的交换或局部重排代替该目标。
  空间达到最优仍可继续优化类别跨度。
- 联合几何搜索前，先逐网格在已有等尺寸占位上按类别和行求数量分配；整个网格内可交换，
  没有行距窗口。按转置后的尺寸分池，固定障碍、网格归属、占用高度与面积不变，
  使用包含模板叶节点的统一树跨度和类型顺序，模板参与数量分组与几何对称性判断。
  同尺寸池按统一树叶节点合组；几何对称性按尺寸、树叶与各网格资格判等。
  模板与实例身份仍用于原位优先回填，不放宽模板一致性约束。
  全部网格的提示阶段合计最多使用准备和压紧后剩余额度的三分之二，
  为联合几何搜索预留三分之一；若此时剩余 3 秒，则按占位 2 秒、几何 1 秒分配。
  提示按可移动物品数量升序处理，每格领取提示阶段当前余量除以尚待处理网格数的额度。
  这只是占位提示的调度，不是逐格独立完成最终排布；几何阶段仍联合所有参与网格。
  提示未用完的额度交回联合几何搜索，双方仍沿用各自连续 0.5 秒无改善的停滞阈值，
  不延长整次 3 秒求解预算。
  `slots[g]=Optimal` 只表示该网格固定占位下的类别分配最优，不表示全局排布最优。
- 全部层级均完成最优证明后才表示整个目标序列最优；
  限时 `Feasible` 仅表示可行结果。
  压缩后的树节点各计一次；已证明固定的目标可以省去常数贡献，
  原公式中的倍率仍须保留，不能改变该网格在总分中的分量。
  不因类别数量少就省略仍有独立作用的聚合目标。
  日志逐网格记录跨度向量和包含坐标目标的完整分数，整次记录求解状态、预算和耗时。

### 自定义类型顺序

- 沿用 SMH 的 27 种物品类型，以平铺列表调整统一树顶层先后；类型内子树继续参与聚合。
  类型及名称见 [README 类型对照](../../README.zh-CN.md#类型顺序)。
  类型判定独立于游戏语言；专用类型先于基类匹配，夜视与热成像不归入普通武器或配件。
- 首次整理生成 `BepInEx/config/com.chouun.stashmaster.category-order.json`。
  文件包含 `enabled` 与字符串数组 `itemTypeOrder`，初始列表采用 SM 的推荐顺序。
  容器置顶，常用装备与同类用途相邻；武器、弹匣、弹药、投掷物依次排列。
  完整顺序见 [README 推荐顺序](../../README.zh-CN.md#类型顺序)。
  默认 `enabled` 为 `true`，从首次整理起按列表中的先后排列。
  已有配置中明确设置的 `false` 保留；关闭只取消类型先后约束，不改变聚合树。
- 首次生成按游戏语言写入类型名；当前提供中文译名，其他语言回退英文类型名。
  中文名称由本项目维护，对应同一组物品类型，不改变分类。
  中文、英文类型名可混写；切换游戏语言或重新启动后仍能读取既有配置。
  已有配置保留原文，不自动翻译或改写。
- 每次整理开始时读取一次配置。未列出的类型按默认顺序补在列表末尾。
  中文与英文先转换为同一类型；重复类型、未知名称、空值或无效 JSON 视为无效。
  无效配置保留上次有效设置并记录错误。
  首次读取即无效时，按未启用处理；读取失败不覆盖用户文件。
- 自定义顺序只用于最终排布，不改变收纳选择、固定物品或网格归属。
  类型先后作为排布条件，求解器在此条件内优化原有空间与聚合分数。
  不预留矩形分区或整行，允许类别边界共享行。
  类型按覆盖区域的纵向中线比较前后，中线相同允许并排。
  类型缺席不参与比较，未识别类型置后；固定物品不计入类型位置。
- 启用顺序时，旧布局若不符合新顺序，不能用旧布局的聚合分数拒绝新顺序。
  顺序改善重置停滞计时。
  顺序尚有反序时，不能仅因高度和跨度达到界限而跳过求解。
  修改顺序或开关后，下次整理重新计算，不复用旧顺序的缓存。
- 预算内未找到符合顺序的完整布局时，相关网格保留原位并提示；不缓存此结果。

### 有限等待与失败

- 收纳阶段最多使用 2 秒，最终排布的全部网格共同使用整次 3 秒的剩余额度。
  收纳未用完的额度结转，例如收纳用了 0.4 秒，最终排布可用 2.6 秒。
- 收纳的多网格联合选择按目标容器单次最多分配 1 秒；
  最终排布不再按容器或网格逐个分配一秒，容器增多不增加总搜索预算。
- 收纳只以面积判断最优；全部候选已放下或达到可收纳面积上限时立即结束。
- 最终排布已证明达到最优，或已有布局同时达到行数、各层类别跨度及行列坐标和的理论界限时，
  可以提前结束；空网格的坐标贡献为零。
  最优界限须考虑未选候选，但不限定物品尺寸、类别数量或容器种类。
- 联合几何搜索连续 0.5 秒没有找到各参与网格完整分数之和更低的布局时，停止搜索并返回最好布局。
  停滞计时从求解器确认首次可行解后开始；预处理不计入停滞时间。
  只有完整总分严格下降才重置计时，同分解、更差解或证明下界变化均不重置。
  分段之间暂停计时，下一段确认可行解后继续累计，不因分段重新获得 0.5 秒。
  停滞退出仍是可行结果，不表示已证明最优；原有总预算继续有效。
  前置占位分配使用相同的停滞判据，但只比较本网格完整分数，受本格占位预算约束，计时独立。
  单格占位停滞不停止后续网格提示或联合几何搜索，所有阶段仍受统一的剩余时间限制。
- 达到时限时采用已有可行结果；没有改进时使用原布局或启发式保底。
  不把限时得到的可行解宣称为全局最优。
- 同一游戏进程内，单网格输入与已应用结果均未变化时，可以复用限时结果，
  避免重复消耗预算；复用不表示已证明最优。
  物品身份、尺寸、类别、类别顺序、必留状态、网格、固定障碍或布局变化时重新计算。
  新分配的求解预算更长时也重新计算。
- 最终排布仍按整次网格集合缓存，逐网格匹配原始输入或已应用输出；
  有任一网格变化则重新规划，缓存命中也重新统计本次实际移动数。
- 求解在后台执行，游戏对象读取、布局应用和移动事务在游戏线程执行。
- 预算约束求解工作；原生库首次初始化、线程调度和游戏事务仍有额外开销，
  不承诺整次整理在 3 秒内结束。
  超出分配额度的调度及保底开销不侵占最终排布的保留额度，
  日志分别记录预算消耗和实际规划耗时。
- 腾出位置失败时不执行依赖该布局的收纳；移动失败的物品留在来源容器。
  移动失败计入结果警告数，日志记录物品、目标容器、网格与具体原因，
  该候选仍可尝试后续规则。
  已成功完成的重排与其他移动保留，不做整次整理的回滚。
- 联合计划中某网格腾位失败，不执行依赖该网格新布局的收纳；
  其他网格可以继续，失败候选仍可尝试后续规则。

## 示例

| 场景 | 预期 |
| --- | --- |
| 空位总面积够，但没有连续空间放入大件 | 尝试重排原有物品，再收进大件 |
| 3×3 空网格，候选为一个 2×2 与三个 1×3 | 优先放入三个 1×3，占满 9 格 |
| 3×3 内原有一个 2×2，另有三个 1×3 候选 | 保留原有 2×2，不为填满而移出它 |
| 容器已满，但已有堆叠未满 | 先补充数量，再考虑余量是否有位置 |
| 再次整理，常规排序或更优布局已稳定 | 不提交位置没有变化的排布 |
| 底部固定物品使总行数无法减少 | 上方散放物品仍正常归拢、排序 |
